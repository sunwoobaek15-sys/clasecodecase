# 개발 기초
> 자주 쓰는 개발 개념을 짧게 정리한 자료.

## Git 기본 명령
git init은 저장소를 만들고, git add로 변경 파일을 스테이징하고, git commit -m "메시지"로 기록을 남깁니다. git status는 현재 상태, git log는 기록을 보여 줍니다. git branch 이름으로 가지를 만들고 git switch 이름으로 옮기며, git merge로 합칩니다. git push는 원격 저장소에 올리고 git pull은 가져옵니다. 커밋 전에 git diff로 무엇을 바꿨는지 확인하는 습관이 좋습니다. 비밀번호와 API 키는 커밋하지 말고 .gitignore에 넣습니다.

## SQL 기본
SELECT 열 FROM 테이블 WHERE 조건으로 행을 조회합니다. ORDER BY로 정렬하고 LIMIT으로 개수를 제한합니다. GROUP BY는 같은 값끼리 묶어 COUNT, SUM, AVG 같은 집계를 하며, 묶은 결과의 조건은 HAVING으로 겁니다. JOIN은 여러 테이블을 키로 연결하는데, INNER JOIN은 양쪽에 모두 있는 행만, LEFT JOIN은 왼쪽 테이블의 모든 행을 가져옵니다. INSERT는 추가, UPDATE는 수정, DELETE는 삭제이며, UPDATE와 DELETE는 WHERE를 빼면 모든 행에 적용되니 조심해야 합니다.

## HTTP 상태 코드
200은 성공, 201은 생성됨, 204는 성공했지만 내용 없음입니다. 301과 302는 다른 주소로 이동하라는 뜻입니다. 400은 요청이 잘못됨, 401은 인증이 필요함, 403은 권한이 없음, 404는 찾을 수 없음, 409는 현재 상태와 충돌, 422는 입력값 검증 실패, 429는 요청이 너무 많음입니다. 500은 서버 내부 오류이고 503은 서버가 일시적으로 이용 불가입니다. 4xx는 요청한 쪽의 문제, 5xx는 서버 쪽의 문제로 보는 것이 기본입니다.

## REST API 기본
REST API는 주소(URL)가 자원을 나타내고 HTTP 메서드가 동작을 나타냅니다. GET은 조회, POST는 생성, PUT과 PATCH는 수정(PUT은 전체, PATCH는 일부), DELETE는 삭제입니다. 데이터는 보통 JSON으로 주고받습니다. GET은 서버 상태를 바꾸지 않아야 하고, 같은 PUT이나 DELETE를 여러 번 보내도 결과가 같아야(멱등성) 합니다. 오류는 상태 코드와 설명 메시지로 알려 줍니다.

## JSON 형식
JSON은 키와 값으로 데이터를 표현하는 텍스트 형식입니다. 객체는 중괄호 {}, 배열은 대괄호 []이며, 키는 반드시 큰따옴표로 감쌉니다. 값은 문자열, 숫자, true/false, null, 객체, 배열만 가능하고 주석과 마지막 쉼표는 허용되지 않습니다. 날짜는 전용 형식이 없어서 보통 ISO 8601 문자열(2026-11-01T09:00:00Z)로 씁니다.

## Python 가상환경과 pip
가상환경은 프로젝트마다 패키지를 따로 설치하는 독립된 공간입니다. python -m venv .venv로 만들고, Windows는 .venv\Scripts\activate, macOS와 Linux는 source .venv/bin/activate로 켭니다. 켠 상태에서 pip install 패키지로 설치하고, pip freeze나 requirements.txt로 목록을 관리합니다. 가상환경 폴더는 git에 올리지 않습니다.

## 시간 복잡도(Big-O) 기초
Big-O는 입력이 커질 때 실행 시간이 얼마나 빨리 늘어나는지를 나타냅니다. O(1)은 입력 크기와 무관하고, O(log n)은 이진 탐색처럼 절반씩 줄이며, O(n)은 한 번 훑는 것이고, O(n log n)은 효율적인 정렬이며, O(n²)은 이중 반복문입니다. 데이터가 천 개 이하면 대부분 차이가 없고, 수십만 개 이상에서 중요해집니다. 먼저 정확하게 만들고, 느릴 때 측정한 뒤 개선하는 것이 순서입니다.
