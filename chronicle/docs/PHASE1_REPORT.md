## 2. 실행 및 테스트 결과

**자동 테스트** (`tests/`, `godot --headless --path . --fixed-fps 60 res://tests/test_runner.tscn`)
- 46개 테스트, 579개 검사 — **전부 통과**, 스크립트 오류·경고 0건 (여러 번 반복 실행해도 동일).
- 범위: 스프라이트·데이터·레벨 무결성, 모든 스크립트 컴파일·모든 씬 인스턴스화, 이동·걷기/달리기·점프 높이·가변 점프·코요테 타임·회피 무적/거리·3단 콤보·강공격 충전·스킬 마나/쿨다운·궁극기 게이지·피격 무적·사망·낙하 복귀, 슬라임 순찰·추격·탄·튀김·사망·변형·슈퍼아머, 베르단 등장·**모든 공격이 0.6초 이상 예고 후 실행**·통나무 명중·뿌리 파동 점프 회피·그로기·2페이즈·사망, 터치 버튼·아날로그 조이스틱·멀티터치 비간섭·UI 크기별 배치, 스테이지 생성·경기장 문·체크포인트·클리어·게임오버.

**자동 플레이 봇** (`-- --bot`): 터치 컨트롤과 같은 입력 액션만 보내고 화면에 보이는 정보(적 위치, 경고 표시)만 읽습니다.
- 최종 코드로 헤드리스 4회 연속 **클리어** (사망 2·0·0·0회, 게임 시간 75~150초). 개발 중 전체 누적으로도 밸런스 조정 이후 실행은 모두 클리어.
- 실제 렌더링(Xvfb + Mesa OpenGL, 1280×720) 실행도 클리어 → `docs/screenshots/`.
- 화면 비율 1280×720(16:9), 2400×1080(20:9), 1600×1200(4:3)에서 HUD·조이스틱·버튼 배치 확인.

**실기기**: 이 환경에는 Android SDK·기기가 없어 **Android 빌드와 실기기 테스트는 하지 못했습니다** (내보내기 프리셋만 준비).

## 3. 개발 중 발견하고 수정한 오류

| # | 문제 | 발견 | 수정 |
|---|---|---|---|
| 1 | 궁극기 자신의 타격이 궁극기 게이지를 41% 다시 채움 | 테스트 | 궁극기 타격은 게이지·마나 미충전 |
| 2 | 강화형 슬라임 3방향 탄 발사 시 런타임 오류(타입 배열) | 테스트 | 타입 배열 생성 방식 수정 |
| 3 | 베르단 예약 공격 정리 시 해제된 노드로 런타임 오류 | 테스트 | 유효성 검사 후 재구성 |
| 4 | 공격자가 죽은 뒤 날아가던 탄이 맞으면 스크립트 오류 | 테스트 | `HitData.copy()`에서 해제된 공격자 처리 |
| 5 | 콤보 전진 스텝이 주인공을 보스 몸 안으로 밀어 넣어 접촉 피해 연속 (첫 봇 실행에서 접촉 피격 32회) | 봇 | 바로 앞에 적이 있으면 전진 정지, 보스 접촉 판정 축소 |
| 6 | 뿌리 파동 점프 성공 구간이 약 77ms로 사실상 회피 불가 | 봇·계산 | 가시가 솟는 0.12초만 판정 → 약 250ms |
| 7 | 시작 시 HUD 마나 바가 비어 있고 HP 숫자 없음 | 스크린샷 | HUD가 현재 값을 직접 읽음 |
| 8 | 4:3 화면에서 레벨 아래 빈 띠 | 스크린샷 | 레벨 바닥 확장, 카메라 높이 보정 |
| 9 | 히트스톱·슬로모션이 실제 시계 기준이라 고정 프레임 실행 시 비결정적 | 테스트 설계 | 시간 배율을 제거한 프레임 시간 기준 |
| 10 | 라벨 29개 중 8개 미검출(다른 라벨 색, 스프라이트와 접촉) | 미리보기 | 시트별 라벨 색 + 위치 힌트 보정 |
| 11 | 마무리 일격·회피·준비 자세 프레임의 기준점이 어긋나 캐릭터가 튐 | 정렬 시트 | 몸통 부품 지정, 머리·발 판정에서 망토·검기 제외 |
| 12 | 보스 이펙트가 너무 커서 런타임 축소가 필요(픽셀 크기 불일치) / 뿌리 가시가 점프 높이보다 큼 | 크기 점검 | 파이프라인에서 게임 크기로 재추출 |
| 13 | 2페이즈 전환 연출(큰 반투명 잎 소용돌이)이 보스 앞에 그려져 보스가 반투명하게 보임 | 스크린샷 → 진단 캡처로 재현 | 보스 주변 오라 이펙트를 캐릭터 뒤 레이어로 이동 |

## 4. 알려진 한계 (미완성으로 남은 부분)

- **실제 Android 기기 미검증**: 멀티터치는 테스트에서 터치 이벤트를 시뮬레이션해 검증했고, PC에서는 마우스→터치 에뮬레이션으로 확인했습니다. 실기기 반응성·발열·성능은 Phase 5 전에 꼭 확인해야 합니다.
- **밸런스**: HP·피해·예고 시간은 봇 기준으로만 조정했습니다. 사람 플레이테스트가 필요합니다.
- **원본 프레임 수**: 주인공 공격은 동작당 1~2프레임(원본 한계), 걷기는 달리기 프레임 재사용, 강화형 슬라임은 단일 프레임 + 절차 애니메이션.
- **지형·배경·UI 아이콘은 절차 생성 임시 아트**(참고 이미지에 없음).
- 사운드 없음(Phase 4), 저장 없음(체크포인트는 실행 중 메모리에만 유지 — Phase 2에서 JSON 저장).
- 크로노스 시트는 배경 제거 후 글로우 가장자리에 흰 잔여 픽셀이 남아 수작업 보정 필요.

## 5. 다음 단계 (Phase 2 — 성장 시스템)

1. JSON 저장 시스템: 버전 필드·마이그레이션·백업 파일·원자적 쓰기(임시 파일 후 교체), 자동/수동 저장.
2. 레벨·경험치(몬스터 처치 보상), 능력치 성장 — `PlayerStats` 런타임 복사본에 적용.
3. 인벤토리·장비(무기/방어구) — 이미 `WeaponData`로 무기별 기술 세트가 분리되어 있음.
4. 스킬 데이터 확장(`AttackData` 기반)과 스킬 슬롯 UI.
5. 병행 권장: Android 디버그 빌드로 실기기 조작감 확인, 주인공 추가 프레임(걷기·공격 중간 프레임) 제작.

Android 빌드 준비물: Godot 4.7.2 내보내기 템플릿, JDK 17, Android SDK(build-tools, platform-tools), 디버그 키스토어 → Godot 편집기 설정에 경로 지정 → `export_presets.cfg`의 "Android" 프리셋으로 내보내기.
